## June 18, 2026

### Where We Are Right Now

**What exists:**
- 63K lines of Rust, 304+ tests passing
- HDC store: 71,900 entries, 272MB, 768-dim embeddings
- Hybrid retrieval: 4/15 (26.7%) on factual Q&A
- NCA language model: 107K params, 100-word vocab, trained on a demo curriculum

**What's broken:**
- Retrieval: 11/15 questions fail (7 because books aren't in corpus, 4 because keyword/HDC fusion isn't strong enough)
- NCA LM: trained on 100-word demo vocab, not real text. No accuracy benchmark.
- Dream cycle: disabled since v0.3.3
- The NCA grid doesn't do anything useful right now

### The Insight Nobody Writes Down

Here's what I learned today that matters:

**The problem isn't the algorithm. It's the division of labor.**

Every attempt to make the NCA grid do everything (store knowledge, retrieve it, generate text, self-organize) has failed. The grid is a dynamical system — it's good at patterns, propagation, and emergence. It's terrible at precise recall.

The HDC store is good at precise recall. It's terrible at generation and adaptation.

The answer isn't one or the other. It's **three systems with clear jobs**:

1. **HDC Store** — remembers what it read (exact, fast, grows forever)
2. **NCA Grid** — learns patterns and generates (slow, organic, gets better with sleep)
3. **Small LLM** — synthesizes answers from retrieved context (the missing piece)

The small LLM doesn't need to be big. A 1B parameter model running through Ollama can read 5 retrieved passages and answer "who wrote Alice in Wonderland?" That's the missing synthesis step. The HDC store finds the passages, the LLM reads them and answers.

This isn't cheating. This is the architecture. RAG systems do this. The difference is SAGE's RAG runs on a potato, the knowledge store is local and private, and the NCA grid will eventually replace the LLM for generation.

Given these passages from books, answer the question.

## Phase 2: Make the NCA Grid Actually Useful (Week 3-4)

**Goal: NCA grid learns patterns from the HDC store during sleep**

The NCA grid's job is NOT storage. Its job is **compression and generation**. During "sleep" cycles:

### Step 6: Consolidation engine (Day 7-9)
Build `src/consolidation/mod.rs`:

1. Scan HDC store for clusters (groups of entries with high cosine sim)
2. For each cluster, extract the common pattern (what makes these passages similar?)
3. Update NCA attractors to represent these patterns
4. The NCA grid becomes a compressed model of what the brain knows

This is the "dream" — but not the broken v0.3.3 dream. The old dream cycle tried to move knowledge between two NCA grids. The new dream moves knowledge from HDC → NCA. One direction. Clean.

### Step 7: NCA generation (Day 10-12)
Once the NCA has learned patterns, it can generate:
- Given a prompt, activate related cells
- Run NCA steps to propagate activation
- Read out the generated pattern

This won't produce coherent text (the 107K param model is too small). But it should produce:
- Relevant keyword suggestions
- Topic clustering
- "Intuition" about what the brain knows

### Step 8: NCA LM training on real text (Day 13-14)
Replace the 100-word demo vocab with a real tokenizer (BPE, 4K-8K tokens). Train on the corpus:
- Use the existing `nca_lm_trainer.rs` 
- Train on actual book text, not curriculum JSON
- Measure top-5 next-token prediction accuracy
- Target: 15%+ top-5 accuracy (random is 0.02% at 4K vocab)

15% sounds low, but it means the NCA has learned something real. And it runs on a potato with 107K params.

**Deliverable:** NCA grid does something useful — it learns from the HDC store during sleep and can generate patterns. Not great patterns, but real ones.

## Phase 3: Make It Run On Anything (Week 5-6)

**Goal: SAGE runs on a Raspberry Pi 4 with 2GB RAM**

### Step 9: Fastembed-only mode (Day 15-16)
Replace nomic-embed-text (274MB, needs Ollama) with All-MiniLM-L6V2 (90MB, bundled via fastembed crate). SAGE already has `fastembed` as a dependency.

This means:
- No Ollama needed for embeddings
- 90MB model vs 274MB
- 384-dim instead of 768-dim (rebuild HDC store)
- Total footprint: 90MB model + 120MB HDC + 40MB NCA = 250MB

### Step 10: Small LLM for synthesis (Day 17-18)
Use qwen3.5:4b (2.5GB) through Ollama for answer synthesis. On a Pi 4 with 4GB RAM:
- 2.5GB LLM + 250MB SAGE + 500MB OS = 3.25GB (fits in 4GB)
- On 2GB Pi: use qwen2.5:1.5b (1GB) instead

For truly minimal hardware (ESP32, Pi Zero):
- Skip the LLM entirely
- Return raw HDC passages (no synthesis)
- The NCA grid provides "intuition" via activation patterns
- This is the "no LLM" mode — pure retrieval + NCA

### Step 11: Continuous learning (Day 19-20)
Wire up the knowledge loop:
- User feeds SAGE documents (text files, web pages, books)
- HDC store ingests them immediately
- Sleep cycle runs NCA consolidation during idle time
- Brain gets smarter the more you use it

### Step 12: P2P knowledge sharing (Day 21)
The libp2p infrastructure already exists. Use it:
- Two SAGE nodes gossip HDC entries
- Each node's brain grows from the other's knowledge
- Federated NCA consolidation (nodes share attractor weights)

**Deliverable:** SAGE runs on a Pi 4, learns from what you read, gets smarter over time, and can share knowledge with other nodes. No API keys. No cloud. No GPU.

## The Outside-the-Box Part

Here's where I want to push:

### SAGE as a Knowledge Commons
What if SAGE nodes formed a P2P network where each node contributes what it learns? Your SAGE reads a book → it shares the embeddings with the network → every other SAGE gets smarter. Not the raw text (copyright), just the embeddings (math).

This is federated learning for knowledge. No central server. No company owns it. The more people run SAGE, the smarter everyone's SAGE gets. It's like BitTorrent for intelligence.

### The NCA as a Biological Model
The NCA grid isn't just a cute trick. It's a model of how biological neural networks work — local interactions, no global coordination, emergent behavior. If we can get the NCA to learn real patterns from the HDC store, we have a computational model of memory consolidation. That's scientifically interesting, not just engineering.

### No-LLM Mode
The most radical idea: SAGE that works WITHOUT any LLM. Pure HDC retrieval + NCA generation. It can't synthesize answers in natural language, but it can:
- Find relevant passages (HDC)
- Show you what it "remembers" (HDC + NCA activation patterns)
- Generate associations (NCA)
- Cluster knowledge (NCA attractors)

This would run on an ESP32. It wouldn't be as useful as the LLM version, but it would be AI that literally runs on a $5 chip. That changes who can have AI.

### The 10-Year Vision
Year 1: SAGE answers questions from books. Runs on a laptop.
Year 2: SAGE learns from everything you read. Runs on a Pi.
Year 3: SAGE nodes share knowledge P2P. The network gets smarter.
Year 5: The NCA replaces the LLM for generation. No external model needed.
Year 10: Everyone has a personal AI that knows what they know, runs on their hardware, and belongs to them.

This is the thing that has to exist. Not because it's profitable, but because a world where everyone has a private, local, self-improving AI is a fundamentally different world than one where three companies own all the intelligence.
