# SAGE v0.6.0 — The Living Brain Architecture (Revision 2)

## The Real Problem (2026-06-18 Post-Benchmark)

After 3 full rebuilds with different chunking strategies:
- v1: 69K chunks, 0/15, 0.77 relevance — tiny fragments dominate
- v2: 66K chunks (min 100 chars), 0/15, 0.75 relevance — short fragments removed
- v3: 73K chunks (overlap + metadata prefix), 0/15, 0.71 relevance — worse!

### Root Cause: Embedding ≠ Answering

Pure cosine similarity over text embeddings **cannot answer factual questions** about text content. "Who wrote Alice in Wonderland?" doesn't semantically match "by Lewis Carroll" — it matches other text about Alice, Wonderland, authors, and writing.

This is the fundamental limitation of pure RAG without a language model to synthesize the answer. The HDC store finds *related passages*, but it can't *extract answers* from them.

### What Actually Works

The HDC store DID work for Sherlock Holmes → Watson (v2, 1/15). Why?
- "Sherlock Holmes' companion" semantically matches passages where Watson is described as Holmes' companion
- The text literally says "Dr. Watson" alongside "Sherlock Holmes"

For "Who wrote X?" — the answer is in a *byline*, not in the prose. The question matches prose about the book, not the byline. This is a different kind of retrieval.

## The Solution: Multi-Modal Retrieval

### 1. Keyword Index (BM25-style)
For exact-match queries ("who wrote X", "what is the capital of Y") — a simple inverted index beats embeddings. "Who wrote Alice in Wonderland?" → keyword search for "Alice" + "Wonderland" + "wrote" → finds byline "by Lewis Carroll".

### 2. HDC Store (Semantic)
For conceptual queries ("what is the main theme of X") — embedding similarity works. "Main theme of The Prince" → finds passages about power and statecraft.

### 3. Generation (NCA + LLM)
For synthesis — take the retrieved passages and generate an answer. This is where the NCA grid and/or a small local LLM comes in.

### Query Flow

1. **Query**: "Who wrote Alice in Wonderland?"
2. **BM25**: Search for keywords → finds chunks containing "Alice", "Wonderland", "Lewis Carroll" (from byline)
3. **HDC**: Embed query → finds chunks semantically related to Alice/Wonderland
4. **Fusion**: Merge results, BM25 weighted higher for factual queries
5. **Synthesis**: Small LLM reads top chunks → "Lewis Carroll"

This is standard RAG architecture. The novelty is:
- **Runs on a potato** (no GPU, no API keys)
- **BM25 is instant** (microsecond lookup)
- **HDC is fast** (650ms for 70K entries, could be <100ms with SIMD)
- **NCA provides generative sleep** (gets smarter over time)

## Implementation Plan (Revised)

### Phase 1: BM25 + HDC Hybrid (Immediate)
- Add a simple inverted index alongside HDC store
- Tokenize chunks at ingestion time
- Query: BM25 + HDC scores fused with reciprocal rank fusion
- Target: 8-12/15 on the benchmark

### Phase 2: Answer Synthesis (Next)
- Use Ollama (or local model) to synthesize answers from top chunks
- "Given these passages, who wrote X?"
- This is the step that actually answers questions

### Phase 3: NCA Consolidation (Later)
- NCA grid learns patterns from Q&A history
- Over time, it can generate answers without the LLM call
- This is the "dream" — the brain gets smarter on its own
