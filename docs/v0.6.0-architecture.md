# SAGE v0.6.0 — The Living Brain Architecture

## Vision

An AI that belongs to everyone. Runs on a Raspberry Pi, a decade-old laptop, a phone. No API keys, no cloud, no GPU required. It learns continuously from what it reads, gets better the more you use it, and its knowledge is yours. It's not a product — it's a digital organism.

## What We Learned (2026-06-18)

### What Works
- **NCA grid is potato-viable**: 40MB brain, 350ms queries, 420ms load on commodity hardware
- **Semantic embeddings are discriminative**: nomic-embed-text gives 0.975 cosine sim between related texts, 0.002 for unrelated
- **Test suite is solid**: 304/304 passing, 63K lines of Rust, real infrastructure
- **Corpus is diverse**: 100 books spanning philosophy, science, world literature, drama, poetry

### What's Broken
- **Hash-based grid positioning destroys retrieval**: Text lands at hash-determined positions, not semantic ones. "What is the capital of France?" finds Dickens, not Paris.
- **Dimension reduction kills signal**: 768-dim → 96-dim → 48-dim strided sampling loses 94% of semantic information
- **Grid saturation**: 64K chunks into 65K cells = 100% fill, everything looks the same
- **NCA diffusion washes out embeddings**: Even with 0.005 diffusion rate, thousands of steps smooth everything to uniformity
- **0/15 factual questions answered correctly** with current architecture

### Root Cause
The NCA grid tries to be both a **knowledge store** (semantic retrieval) and a **dynamical system** (self-organization, growth, repair). These are fundamentally different requirements:
- Retrieval needs **precision**: exact embeddings, minimal interference, high dimensionality
- Dynamics need **smoothness**: local interactions, diffusion, self-organization

Forcing both into the same 256×256 grid with 48 embedding channels doesn't work. The dynamics win and the retrieval loses.

## Research Findings

### 1. Hyperdimensional Computing (HDC / VSA)
**What it is**: Represent information as 10,000-bit (or 10,000-dim) pseudo-random vectors. Store knowledge through binding (element-wise XOR or multiply) and superposition (majority vote). Retrieval is exact-match via cosine similarity — no training needed.

**Why it matters for SAGE**:
- **Runs on anything**: 10K-bit vectors are just bit arrays. A Pi can store millions of them.
- **No dimension reduction**: Full embedding fidelity, no 768→48 bottleneck
- **Associative memory**: Query by similarity, not by position. No hash collision.
- **Composable**: Bind (role-filler pairs) and superpose (sets) to build structured knowledge
- **Noise-robust**: HDC vectors are naturally fault-tolerant. Drop bits, still works.

**Key papers**:
- "Attention as Binding: A Vector-Symbolic Perspective on Transformer Reasoning" (2512.14709) — shows transformers approximate VSA
- "Encoder-Free Knowledge-Graph Reasoning with LLMs via Hyperdimensional Path Retrieval" (2512.09369) — HDC for KG reasoning without encoders
- "A wave-geometric duality for hyperdimensional computing" (2604.22863) — mathematical foundation

**SAGE application**: Replace the NCA grid's knowledge channels with an HDC store. Keep the NCA grid for dynamics/visualization, but store knowledge as full-dimensional hypervectors. Retrieval becomes cosine similarity over the HDC store, not grid scanning.

### 2. Neural Cellular Automata for Generation (NCA-LM)
**What it is**: The paper "Training Language Models via Neural Cellular Automata" (2603.10055) shows that NCA-generated synthetic data can pre-train LLMs with only 164M tokens (vs 1.6B from Common Crawl). NCA dynamics produce language-like statistics that transfer to reasoning tasks.

**Why it matters for SAGE**:
- NCAs can generate training data cheaply, forever, on any device
- NCA complexity can be tuned by domain (simpler for code, complex for prose)
- The NCA grid's purpose might not be storage — it might be **generation**

**SAGE application**: The NCA grid becomes a generative engine, not a storage engine. It learns the statistics of language and can produce novel training data. The actual knowledge storage moves to HDC.

### 3. Kolmogorov-Arnold Networks (KAN)
**What it is**: Replace fixed-weight linear layers with learnable univariate functions (splines). KANs can be much smaller than MLPs for the same task, with better interpretability.

**Why it matters for SAGE**:
- **Parameter efficiency**: KANs can match MLP performance with 10x fewer parameters
- **Interpretability**: You can see what each function node does
- **SAGE already has this**: `src/inference/kan.rs` has KanLayer and KanNetwork

**SAGE application**: Use KAN layers instead of MLP for the NCA update rule. A 4×4 KAN grid could replace the current 144→1024→384→16 MLP, reducing parameters by 10x and making the brain fit in less memory.

### 4. Reservoir Computing with Critical NCAs
**What it is**: "Reservoir Computing with Evolved Critical Neural Cellular Automata" (2508.02218) shows that CA at the edge of chaos (criticality) have maximum computational power. SAGE already has criticality metrics (`src/inference/criticality.rs`).

**Why it matters for SAGE**:
- Critical NCAs need fewer cells for the same computation
- Self-organized criticality means the system tunes itself — no manual parameter adjustment
- SAGE already measures branching ratios, Lyapunov exponents, and avalanche distributions

**SAGE application**: Drive the NCA dynamics toward criticality using the existing CriticalityRegularizer. The brain self-organizes to maximum computational power.

### 5. Differentiable Logic CA
**What it is**: "Differentiable Logic Cellular Automata" (2506.04912) combines NCAs with differentiable logic gates. During training, it's differentiable. At inference, it becomes pure boolean logic — zero floating-point ops, runs on any hardware.

**Why it matters for SAGE**:
- **Ultimate potato-class**: Boolean CA needs no FPU. Runs on microcontrollers.
- **Training is still gradient-based**: Can learn with backprop, deploy as logic gates
- **SAGE already has BinaryNCA** (`src/inference/binary_nca.rs`)

**SAGE application**: Long-term path to truly minimal hardware. Train as continuous NCA, quantize to binary NCA, deploy as logic circuits. The brain runs on an ESP32.

### 6. Complementary Learning Systems Architecture
**What it is**: "Attention Is Not Retention" (2601.15313) argues biological memory uses two systems: a fast hippocampal system (sparse, pattern-separated, episodic) and a slow neocortical system (distributed, statistical, semantic). Current AI conflates these.

**Why it matters for SAGE**:
- This is exactly SAGE's problem — trying to do episodic storage AND semantic generalization in one grid
- The solution is **two stores**: fast episodic (HDC, exact recall) + slow semantic (NCA, learned patterns)
- Knowledge transfers from episodic → semantic during "sleep" (consolidation)

**SAGE application**: Dual-store architecture. HDC for exact knowledge recall (what was said, facts, episodes). NCA for learned patterns, generation, and intuition. A consolidation cycle moves knowledge from HDC → NCA during idle time.

### 7. Tsetlin Machines
**What it is**: Machine learning using propositional logic (AND/OR/NOT). No floating-point, no gradients. Learns by reinforcing/penalizing clause outputs. Runs on CPUs at high speed.

**Why it matters for SAGE**:
- **Truly resource-free**: Pure integer arithmetic, no FPU needed
- **Interpretable**: Every learned pattern is a logical formula you can read
- **Competitive**: Matches or beats random forests on many tasks

**SAGE application**: Could replace parts of the query router or specialist decision-making with Tsetlin machines for zero-FPU inference.

### How It Works

#### 1. Knowledge Ingestion (Learning)
```
Text chunk → Embed (nomic/fastembed) → 768-dim vector
                                          │
                              ┌───────────┴───────────┐
                              │                       │
                          HDC Store                NCA Grid
                          (immediate,              (async,
                           exact)                  consolidates)
```

- Every text chunk is embedded and stored in the HDC store immediately
- The HDC store is a flat array of hypervectors + text — no grid, no hashing, no collision
- Retrieval is cosine similarity over all vectors (O(n) but n=10K vectors × 768 dims is fast)
- The NCA grid receives a signal but doesn't need to store the text

#### 2. Knowledge Retrieval (Querying)
```
Question → Embed → 768-dim vector
                        │
                Cosine similarity vs HDC store
                        │
                Top-K results (exact text)
                        │
                ┌───────┴───────┐
                │               │
            Return text    Feed to NCA for
            directly       generation/summary
```

- Factual questions: Direct HDC retrieval. "What is the capital of France?" → find the closest stored passage. Works because 768-dim cosine sim is meaningful.
- Creative questions: NCA generates from retrieved context. "Write a poem about Paris" → HDC retrieves Paris passages → NCA generates.
- No dimension reduction. No hash positions. No grid saturation.

#### 3. Consolidation (Sleep)
```
During idle cycles:
  1. Scan HDC store for repeated patterns
  2. Update NCA attractors to represent common knowledge
  3. Compress old HDC entries (merge similar ones)
  4. NCA generates synthetic variations → store back to HDC
```

- The NCA grid learns the *shape* of knowledge, not the specific facts
- Over time, the NCA can generate plausible text in the style of what it's learned
- The HDC store remains the source of truth for facts

#### 4. P2P Knowledge Sync
```
Node A ←→ Node B
  HDC entries sync via gossip (small, bounded)
  NCA grid sync via existing libp2p diff protocol
```

- HDC entries are small (768 floats = 6KB each). Sync 1000 entries = 6MB.
- NCA grid diffs are already implemented
- Two nodes can share knowledge and both get smarter

### Why This Works Better

| Problem | Old Architecture | New Architecture |
|---------|-----------------|-----------------|
| Retrieval accuracy | 0/15 (hash position, 48-dim) | ~12-14/15 expected (768-dim cosine) |
| Grid saturation | 100% at 64K chunks | N/A (HDC is flat array, no grid) |
| Dimension loss | 768 → 48 (94% lost) | 768 → 768 (0% lost) |
| Hash collision | Massive (64K in 65K cells) | None (each entry is independent) |
| NCA dynamics | Destroys retrieval | Enhanced (no retrieval duty) |
| Potato-class | ✓ (40MB) | ✓ (HDC: 10K × 6KB = 60MB, NCA: 40MB) |
| No API keys | ✓ | ✓ |
| Continuous learning | ✓ (but degrades) | ✓ (HDC grows, NCA consolidates) |

### Resource Budget (Raspberry Pi 4, 4GB RAM)

| Component | Memory | CPU | Disk |
|-----------|--------|-----|------|
| HDC store (10K entries × 768-dim f32) | 30MB | ~50ms scan | 30MB |

Fits comfortably in 4GB. Could run on 2GB with fastembed-only.

## Implementation Roadmap

### Phase 1: HDC Store (Week 1-2)
**Goal**: Working semantic retrieval with 0% dimension loss

1. **Implement HDC store** (`src/hdc/mod.rs`)
   - `Hypervector` struct: 768-dim f32 (or configurable)
   - `HdcStore` struct: Vec<Hypervector> + Vec<String> (parallel arrays)
   - `query(&self, embedding: &[f32], k: usize) -> Vec<(f32, &str)>` — cosine sim, top-k
   - `insert(&mut self, embedding: &[f32], text: &str)`
   - `save/load` to binary file (`~/.sage/hdc_store.bin`)
   - Batch insert with optional dedup (cosine sim > 0.98 = skip)

2. **Wire into KnowledgeLoop**
   - `encode_text()` returns features (existing)
   - New: also store to HDC alongside NCA grid
   - `query()` checks HDC first, then NCA as fallback
   - Offline engine uses HDC only

3. **Benchmark**
   - Re-run the 15-question offline Q&A
   - Target: 10/15+ correct (up from 0/15)
   - Measure query latency (target: <100ms for 10K entries)

### Phase 2: Dual-Store Integration (Week 3-4)
**Goal**: NCA grid freed from retrieval duty, becomes dynamics/generation engine

1. **Separate concerns**
   - NCA grid: learning dynamics, attractors, self-organization (no text storage)
   - HDC store: all text/knowledge retrieval
   - Remove embedding channels from NCA (keep only activation + dynamics channels)
   - Smaller NCA grid: 256×256×16 channels (down from 80) = 8MB

2. **Consolidation engine** (`src/consolidation/mod.rs`)
   - Runs on cron/heartbeat during idle
   - Scans HDC for frequent patterns
   - Updates NCA attractor weights
   - Compresses HDC (merge entries with cos sim > 0.95)

3. **KAN update rule**
   - Replace MLP in NCA with KAN layers (existing `src/inference/kan.rs`)
   - Fewer parameters, better interpretability
   - Benchmark parameter count and training speed

### Phase 3: Specialist Employee (Week 5-6)
**Goal**: SAGE can actually work as a knowledge employee

1. **Define specialist profile**: "Knowledge Assistant"
   - Reads documents, answers questions about them
   - Summarizes, cross-references, finds contradictions
   - No code generation, no complex reasoning — just knowledge work

2. **End-to-end task**:
   - Give SAGE 10 documents
   - Ask 20 questions
   - Measure accuracy (target: 70%+)
   - Measure latency (target: <2s per question including embedding)

3. **Self-improvement loop**:
   - Every question answered → stored in HDC
   - Correct answers reinforced, wrong answers flagged
   - NCA consolidates patterns from Q&A history

### Phase 4: P2P Knowledge Network (Week 7-8)
**Goal**: Multiple SAGE nodes share knowledge and all get smarter

1. **HDC sync protocol**
   - Gossip protocol for HDC entries (already have libp2p)
   - Selective sync: only share entries above confidence threshold
   - Dedup across nodes (cosine sim check before accepting)

2. **Federated consolidation**
   - Nodes share NCA attractor weights periodically
   - Average/merge weights (federated learning style)
   - Each node's NCA learns from all nodes' HDC stores

### Phase 5: Minimal Hardware (Week 9-10)
**Goal**: SAGE runs on a Raspberry Pi Zero (512MB RAM)

1. **Binary NCA mode**
   - Quantize NCA grid to binary (existing `src/inference/binary_nca.rs`)
   - Use differentiable logic CA for update rule
   - Zero floating-point ops in the NCA

2. **HDC compression**
   - Compress hypervectors to int8 or binary
   - Use product quantization for large stores
   - Target: 10K entries in 10MB (down from 30MB)

3. **Fastembed-only mode**
   - No Ollama needed. All-MiniLM-L6V2 (90MB) for embeddings.
   - Total footprint: 90MB model + 10MB HDC + 8MB NCA = 108MB
   - Runs on anything with 512MB RAM

## What Makes This Different

### Not Another LLM
SAGE doesn't generate text by predicting the next token. It retrieves knowledge by semantic similarity (HDC) and generates patterns through self-organizing dynamics (NCA). It's a fundamentally different architecture.

### Not Another Vector Database
Vector databases (Pinecone, Weaviate) store embeddings but don't learn. SAGE's HDC store is coupled to an NCA grid that consolidates, generates, and self-organizes. The brain gets smarter, not just bigger.

### Not Another RAG System
RAG systems retrieve chunks and feed them to a separate LLM. SAGE's retrieval and generation are integrated — the NCA grid learns from what the HDC stores, and can generate novel patterns from those learnings.

### For Everyone
- No API keys. No cloud. No GPU.
- Runs on hardware from 10 years ago.
- Knowledge is local, private, yours.
- Nodes can share knowledge peer-to-peer.
- The more you use it, the smarter it gets.
- The more nodes on the network, the smarter everyone gets.

## Key Decisions to Make

1. **HDC dimension**: 768 (match nomic) or 10,000 (traditional HDC)? Higher dim = better retrieval but more memory.
2. **NCA grid size**: Keep 256×256 or go smaller (128×128 = 16x less memory)?
3. **Embedding model**: nomic-embed-text (768-dim, 274MB, needs Ollama) or AllMiniLM-L6V2 (384-dim, 90MB, bundled)?
4. **Consolidation frequency**: Real-time (every insertion) or batch (during idle/sleep)?
5. **P2P protocol**: Keep libp2p gossip or move to simpler HTTP sync?
