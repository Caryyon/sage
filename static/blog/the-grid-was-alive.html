The Grid Was Alive. Then We Ran It.

SAGE's NCA knowledge grid was sitting idle during every conversation — a static hash map pretending to be a brain. Here's how we fixed that, and what changes when the cellular automata actually run.

The Embarrassing Truth

We had a problem we weren't fully admitting to ourselves. The NCA grid wasn't computing anything during chat.

The architecture looked right on paper: text encodes into a 32×32 cellular automata grid, the grid stores knowledge as emergent patterns, knowledge retrieves back out to inform LLM responses. We'd written the reservoir computing proof showing a linear readout can decode token predictions from NCA dynamics with 100% top-5 accuracy. The math checked out.

But in the actual running system? The grid was static. You'd encode a message, the cell states would get written, and then... nothing. The cellular automata rules sat dormant. No update steps. No emergent dynamics. When retrieval happened, we were doing a lookup against a frozen snapshot, not reading from a living computational substrate.

A brain that doesn't fire isn't a brain. It's RAM.

What "Running" the Grid Actually Means

In cellular automata, each cell updates its state based on its neighbors according to a local rule. The interesting part is what happens when you iterate: local rules create global behavior. Patterns propagate, interfere, stabilize, and reorganize across the grid without any central coordination. This is the computational property we're trying to harness — and it only exists when the automata are actually running.

The fix sounds obvious in hindsight: run update steps. But the question was when, and how many, and what do you do between updates?

We landed on a three-phase cycle that runs on every chat turn:

USER MESSAGE → ENCODE INTO GRID →
3× NCA UPDATE STEPS (react to new input)
↓
ATTENTION RETRIEVAL (read relevant patterns)
↓
LLM GENERATES RESPONSE
↓
DREAM STEPS (consolidate, self-heal)

Three update steps before retrieval gives the grid time to react to what just came in — letting the new information propagate through neighboring cells and settle into a stable attractor. Then we retrieve. Then, after the LLM has responded, we run additional dream steps to consolidate the new knowledge into longer-term patterns.

Dream Steps and Freerun Repair

The dream step concept came from neuroscience, specifically sleep consolidation theory: memories don't stabilize during waking, they stabilize during downtime when the brain replays and integrates experience.

For SAGE, dream steps are NCA update iterations that run without any input injection. The grid evolves freely, driven only by its internal dynamics. This does two things:

  • Consolidation: Patterns that were freshly encoded get a chance to settle. Weak activations that don't fit into the existing grid structure naturally decay. Strong signals that align with existing patterns get reinforced.
  • Repair: The grid can drift over many conversations — cells that should be quiet start accumulating noise, hot spots cluster in ways that interfere with retrieval. Freerun repair steps push the grid back toward its learned stability attractor, preventing degradation over time.

Without freerun repair, we were seeing grid saturation after roughly 50 conversation turns — all cells converging to similar activation levels, destroying the pattern differentiation that makes retrieval meaningful. Repair keeps the grid healthy indefinitely.

The AttentionDecoder: From Grid State to Context Vector

Running the grid was step one. Getting useful information out of it required a different kind of work.

The naive approach to retrieval — hash the query, look up a cell, return the stored text — breaks down once the grid is actually computing. Cell states don't map cleanly to discrete memories anymore. They're continuous activations shaped by the interference patterns of everything the grid has processed. You can't just ask "what's in cell (14, 22)?"

We needed something that could attend across the full grid and pull out the information most relevant to the current query. Enter the AttentionDecoder.

The architecture is cross-attention with a thalamic spatial gating twist. The query comes from the current input embedding. Keys and values come from all 1,024 cells of the 32×32 grid. A spatial gate — learned weights that vary by grid position — modulates how much each region contributes. The output is a context vector that captures what the grid knows about the current topic.

Why "thalamic"? The thalamus in the brain acts as a relay station and gating mechanism — it doesn't process information so much as it controls what gets routed to the cortex at any given moment. Our spatial gate plays the same role: it learns which grid regions are informationally relevant for different types of queries, and suppresses the rest. Less noise, better signal.

When Ollama embeddings are available, the retrieval path uses cosine similarity between the query embedding and cell embeddings to identify the most relevant grid regions before the attention pass. When embeddings aren't available, we fall back to pure spatial attention across the full grid. Both paths produce a context vector that gets prepended to the LLM prompt.

The Difference in Practice

Before this update, SAGE's NCA "knowledge" was decorative. The grid would get written, the retrieval call would happen, and whatever came back was vaguely related to recent conversations at best — basically a noisy recency buffer.

With live updates and the AttentionDecoder wired in, the character of the knowledge retrieval changed. The grid reacts to context. A question about a topic you discussed three sessions ago activates different grid regions than one about a topic from an hour ago. Related concepts cluster. The dynamics are doing something that looks, from the outside, like thinking.

That's not a small thing. It's the difference between a system that stores conversations and one that processes them.

What's Still Hard

We want to be honest about the current state. The update steps add latency — not catastrophic, but measurable. On a modern CPU, three NCA update steps on a 32×32 grid take around 2ms. Dream steps add a few more. It's fast enough that users won't notice, but it's time we're spending on every turn.

The bigger open question is retrieval quality at scale. Our experiments show strong results over short to medium conversations. Longer sessions — hundreds of turns, weeks of use — are still being characterized. We know freerun repair helps. We don't know yet whether it's sufficient to maintain retrieval quality indefinitely, or whether we'll need a more aggressive consolidation strategy.

We're also still learning how the grid organizes itself. The emergent structure isn't something we control directly — it's a property of the update dynamics. Sometimes related topics cluster in ways that improve retrieval. Sometimes they don't. Understanding and nudging that organization without destroying it is an active area of work.

The Persistent Identity Fix

One more thing landed in this release: persistent libp2p identity for testnet nodes.

Previously, every time a SAGE node restarted, it generated a fresh Ed25519 keypair and appeared as a new peer to the network. This made it impossible to build reputation, persistent connections, or meaningful peer history — the fundamental building blocks of the decentralized network we're working toward.

Now node identity is derived from a seed stored locally. Restart the node, same PeerId. The network recognizes you as the same peer across sessions. This sounds minor but it's a prerequisite for everything that depends on trust and continuity in the peer mesh.

Version 0.2.4

All of this shipped as v0.2.4. The grid is alive now — actually running, actually computing, actually contributing to the responses you get. The architecture we described in the whitepaper is finally the architecture that's running.

There's still a long way to go. But this was the step that made SAGE's core claim true in practice, not just on paper.
