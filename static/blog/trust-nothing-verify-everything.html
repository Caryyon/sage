Trust Nothing, Verify Everything

A decentralized AI network that accepts knowledge from anonymous peers is a target. Here's how we closed SAGE's poisoning hole, made knowledge sync actually efficient, and fixed a capacity collapse bug that would have silently killed the grid at scale.

The Attack We Had to Fix

SAGE's core proposition is that nodes share knowledge with each other. You learn something, your grid encodes it, a diff propagates to nearby peers, they integrate it. The network gets smarter collectively, not just individually.

That's a compelling story. It's also an obvious attack surface.

Before this update, there was nothing stopping a malicious peer from broadcasting arbitrary KnowledgeDiffs to the network. No authentication. No signatures. A node would receive a diff, run a basic sanity check on the magnitude and stability values, and integrate it if it passed. A motivated attacker could craft diffs that passed the magnitude check while injecting adversarial patterns — slowly steering the grid of every node that synced with them toward a poisoned state.

The threat model: An attacker runs one or more nodes, generates plausible-looking KnowledgeDiffs, and broadcasts them to the gossip network. Every node that integrates these diffs gets poisoned. Because NCA grids are self-organizing, the poisoned patterns can spread through the grid's own update dynamics even after the malicious peer disconnects.

We knew this was a problem before we built the gossip protocol. We just needed to get there.

Ed25519 Signatures on Every Diff

The fix is mandatory cryptographic authentication: every KnowledgeDiff is now signed with the originating node's Ed25519 private key, and every receiving node verifies the signature before processing.

Ed25519 is the right choice here for several reasons:

  • Speed: Signing and verification are fast — relevant when you're processing gossip at scale. Ed25519 verification runs in microseconds on modern hardware.
  • Small signatures: 64 bytes per diff. At the volume of gossip we're targeting, that's negligible overhead.
  • Deterministic: No randomness in signing means no possibility of catastrophic key leakage through bad RNG (unlike older ECDSA schemes).
  • Tie-in with libp2p identity: SAGE nodes already generate Ed25519 keypairs for their libp2p PeerId. We can reuse the same key material for diff signing — no extra key management for node operators.

The signature covers the full diff payload: the grid delta values, the originating node identity, and a timestamp. A receiver that can't verify the signature against a known peer key rejects the diff outright. Unknown senders are held in a quarantine queue until enough reputation data accumulates to make a trust decision.

Signatures don't stop everything. A compromised key, a colluding cluster of peers, or a Sybil attack can still inject bad data. But they dramatically raise the cost of poisoning and make attacks attributable. You can revoke a key. You can't revoke anonymous bytes.

GridDelta v2: Real Deltas for Real Learning

Authentication was the security fix. GridDelta v2 was the efficiency fix — and it turned out to be equally important.

The original GridDelta format sent the full grid state as the "diff." Not a delta between two states — the entire 32×32×N channel grid, serialized and broadcast. We called it a diff. It wasn't.

This had two problems:

  1. Bandwidth: Full grid snapshots are large. On a 32×32 grid with 26 channels of f32 values, each "diff" was around 100KB. Gossip at any meaningful node count would saturate the network.
  2. Semantics: Full state snapshots mean the receiving node replaces its grid with the sender's. That's not learning from a peer — that's being overwritten by them. The receiver loses everything it learned locally that isn't reflected in the sender's grid.

v2 sends true deltas: the signed difference between a node's grid state before and after processing a message. Receiving nodes apply the delta to their own grid using a weighted sum — the Delta Sum Learning rule. Their local knowledge is preserved and the peer's learning is integrated proportionally.

Property GridDelta v1 GridDelta v2
What's transmitted Full grid state (~100KB) True delta (typically <5KB)
Integration method Replace receiver's grid Weighted sum (local + peer)
Local knowledge preserved No Yes
Symmetric learning No (sender dominates) Yes (both contribute)
Bandwidth at 100 nodes 10MB/sync <500KB/sync

The bandwidth improvement is obvious. The semantic improvement is more subtle but more important. Delta Sum Learning means every node in the network is an independent learner that benefits from peer knowledge without surrendering its own. The network converges toward shared understanding through many small adjustments, not through any single node imposing its state.

The Capacity Collapse Bug

While we were working on deltas, we found a bug that would have quietly destroyed the grid's knowledge capacity as it grew.

The text-to-grid encoder worked by projecting input tokens into cell positions via a strided slot assignment — basically dividing the grid into buckets and hashing each token into a bucket. The problem: each cell had a capacity of one text slot. Once a cell was written to, subsequent tokens that hashed to the same position would overwrite the previous value.

On a fresh grid with sparse usage, this is fine. You've got 1,024 cells and not many tokens competing for the same positions. But as the grid fills up — as you have longer conversations, more sessions, more diverse topics — collisions accumulate. Not gracefully degrading, but silently collapsing. Older, less recently-used knowledge gets evicted to make room for newer encodings, with no trace left behind.

We found this while characterizing grid behavior at scale. After a few hundred encoding events, the grid was essentially a rolling window of recent inputs, not a long-term knowledge store. Everything we'd built on top of that assumption — the dream steps, the consolidation, the retrieval — was operating on data that was already stale.

The fix was multi-text storage per cell: each cell now maintains a small buffer of recent encodings, with a soft capacity limit and an LRU eviction policy when the buffer is full. Collisions still happen, but older knowledge degrades gracefully rather than getting stomped. Grid capacity scales with conversation length instead of collapsing past a threshold.

Lesson learned: Test your assumptions at scale, not just on happy-path examples. The capacity collapse only manifested at around 150-200 encoding events — well past what we'd been testing interactively. We needed load tests, not just smoke tests.

The Random Projection Encoder

While we were in the encoder, we replaced the strided slot projection with a seeded random projection matrix. This sounds like a minor implementation detail. The results weren't.

Strided slot assignment creates systematic patterns in how tokens map to grid positions — tokens with similar hash values end up in adjacent cells, creating clustering that's an artifact of the hash function, not the semantics of the input. A random projection matrix breaks this up. Each token gets projected into a random-but-deterministic position in the grid's high-dimensional state space, based on a seeded RNG tied to the token value.

The practical effect: related concepts spread across the grid instead of clustering by hash proximity. This is better for the NCA dynamics because information about a topic is now distributed through the whole grid, not localized in one region. The cellular automata have more surface area to work with when propagating and associating knowledge.

What This All Adds Up To

Authentication closes the most obvious attack vector on the network. True delta learning makes sync efficient and semantically correct. Multi-text cell storage prevents silent capacity collapse. Random projection encoding improves how knowledge distributes across the grid.

None of these fixes are glamorous. There's no benchmark to put in a headline. But they're the difference between a network that works reliably at scale and one that looks good in a demo and falls apart in production.

SAGE is still early alpha. There are more edge cases to find, more attack surfaces to characterize, more scaling behavior to understand. But the foundation is getting solid. These are the kinds of problems you have to solve before you can build the things that actually matter on top.
